# 01 Why Dandy Exists

**Takeaway:** Agents forget everything between sessions; Dandy is the state layer that remembers, so plan and code stay one thing.

**Format:** fully animated, Charlie voiceover as Dandy Man. Dandy Man stands at a blackboard and explains
the builder's story; the classroom is the setting, not a bit. No "class" roleplay. Everything drawn on the
blackboard uses chalk-style versions of the motifs (graph, session reset, context rot).

## Narration, read straight through

A builder and his agent have a great night. Schema, decisions, half the thing built.

Next morning, new session. The agent remembers none of it.

This is context rot. Notes, markdown files, planning tools all rot too, because a human has to keep them current. So the plan says one thing and the code says another.

Dandy is the state layer. One place that knows what your software is, kept current by the agents themselves.

Your product is a graph of projects with typed inputs and outputs. Every agent reads it before it starts and writes back what it changed. Change something upstream, and everything downstream knows.

Next morning, new session. The agent picks up exactly where it left off.

Pick up where you left off. Every time.
