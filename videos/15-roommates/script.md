# 15 Roommates: Two Builders, One App

**Takeaway:** When two people build the same app with their own agents, neither agent knows what the other one
did, so they keep redoing each other's work. Point both at one live map and each agent sees what is built and
what the other is working on before it starts.

**Format:** real-life use case (same kind as 02 Maya). Charlie narrates plainly, no Dandy Man, soft end card
without him. Show more than tell: a few short lines of narration, the screen carries the story. Claude Code is
named outright. The project is ordinary: a bill-splitting app two roommates are making for their own apartment.

**Look (new, proposed): the apartment cutaway.** A dollhouse cross-section at night, stacked for the vertical
frame: Sam's room on top (warm lamp, teal accents), Jo's room on the bottom (cool lamp, coral accents), and
between them a band of wall where the shared app lives, drawn as a phone screen with three pages: Bills, Chores,
Groceries. Each roommate sits at a desk with a monitor showing their Claude Code chat. Whatever an agent builds
or changes travels along a wire from that room into the phone in the wall, in that roommate's color, so you can
always see whose work is whose. Nights and mornings pass through the windows (moon, then sun). Cozy and a
little funny, in the family of the Maya room but its own place. Brand purple appears only when Dandy does: the
wall band becomes the map.

**Cast:** Sam and Jo, two new figures in the Maya style (cartoonish, a bit realistic). Seen from the side at
their desks; no dialogue, only texts.

**Target length:** about 35 s (82 narrated words). Status: draft v1, Nov 23. No render yet.

## Narration, read straight through

Sam and Jo are building an app to split bills for their apartment.
Each one works at night, with their own Claude Code.

The problem: neither agent knows what the other one did.
So every morning, something one of them built has been redone.

Then they pointed both agents at Dandy.

Now each agent checks the same live map before it starts.
It sees what's built, and what the other one is working on right now.

Same app. Two builders. One map.

## Accuracy notes

- The failure is real and ordinary: an agent starting a session sees the code but not what another person's
  agent intended or just did, so it rebuilds or replaces things. We show pages being redone, not data loss.
- "Checks the same live map before it starts": agents connected to Dandy read the product's pieces and their
  status first. "What the other one is working on right now": Dandy shows which agents are active on which piece
  and a piece being worked on has one writer at a time.
- The closing line says "one map", not "nothing ever breaks". No claim about speed, tokens or cost.
- Sam and Jo are invented; no customer is named or implied.

## Messaging check

- Problem first, product second. Plain description of what Dandy does; no "state layer", no banned phrases, no
  long dashes. Claude Code named as the tool they use, nothing implying an endorsement.
